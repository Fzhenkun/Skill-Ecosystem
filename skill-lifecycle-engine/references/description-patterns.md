# Description Patterns

## Goal

Write frontmatter descriptions that trigger on the right requests and stay out of the way of unrelated work.

## Strong Description Formula

Include all of the following:

1. What the skill does.
2. When it should be used.
3. High-signal keywords and synonyms.
4. Explicit exclusions.
5. Bilingual trigger words when the working environment is bilingual.

## Patterns

### Positive enumeration

List the exact scenarios that should trigger the skill.

Example:

```text
Use when Codex needs to create a new skill, repair a partial skill, optimize skill triggering, split a large skill into references, or establish a maintenance workflow.
```

### Keyword carpet

Add synonyms, abbreviations, and alternate phrasings that real users may use.

Example concepts:

- skill creation
- skill packaging
- SKILL.md
- trigger optimization
- reference routing
- maintain skill
- 优化技能
- 创建技能
- 维护 skill

### Reverse exclusion

State what not to use the skill for.

Example:

```text
Do not use for ordinary application coding unless the task is specifically about Codex skill construction or maintenance.
```

## Anti-Patterns

Avoid:

- vague descriptions such as "help with automation"
- body-only trigger guidance that never appears in frontmatter
- long unstructured paragraphs with no concrete scenarios
- descriptions that overlap heavily with unrelated skills
