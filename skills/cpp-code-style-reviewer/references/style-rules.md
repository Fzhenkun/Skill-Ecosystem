# C++ Style Rules

这些规则根据参考图片中的 Google C++ Style Guide 批注整理。项目级规范、编译器约束和现有 `.clang-format` 优先；发现冲突时同时报告两者。

## 严重性

- **高**：可能造成未定义行为、编译问题、接口误用或明显维护风险，例如 C 风格转换、`NULL`、缺失头文件自包含、危险宏。
- **中**：违反团队统一风格并增加审查成本，例如命名、include 顺序、缩进、头文件保护。
- **低**：可读性或一致性建议，例如行宽、注释位置、过度复杂的表达式。

## 检查清单

1. 文件头：保留正确的版权/许可证信息；新文件若项目要求，应使用项目模板。
2. 头文件：头文件可独立编译；只包含直接使用的声明；项目头文件优先，其次 C 系统头、C++ 标准库、第三方库；同组内排序稳定。
3. 保护：使用唯一的 `PROJECT_PATH_FILE_H_` 风格 include guard，或项目明确启用的 `#pragma once`。
4. 格式：2 个空格缩进，不使用 tab；运算符和逗号周围留空格；控制语句与括号间留空格；`else` 与前一个 `}` 同行；避免超长行，默认阈值 80 列（URL、长字符串和许可证行可例外）。
5. 命名：类型、类、枚举、函数对象使用 PascalCase；变量、函数、命名空间和文件使用 snake_case；常量可用 `kPascalCase`；宏使用 `UPPER_SNAKE_CASE` 且尽量避免。
6. 命名空间：使用具名命名空间；不要在头文件写 `using namespace ...`；命名空间内容不额外缩进；短的内部实现可用匿名命名空间。
7. 类：成员顺序保持 public/protected/private；一个参数的构造函数通常加 `explicit`；拷贝/移动语义和析构函数要明确；只读成员函数加 `const`。
8. 指针和引用：声明符靠类型一侧（`int* p`, `const std::string& name`）；优先引用、智能指针和 RAII；避免裸 owning pointer。
9. 现代 C++：使用 `nullptr` 替代 `NULL`/`0` 指针值，使用 `static_cast` 等命名转换替代 C 风格转换；优先 `override`、`constexpr`、范围 for 和标准库算法。
10. 控制流：switch 完整处理 `default`；返回值不要无意义地加括号；不要用宏表达常量、函数或复杂逻辑。

## 自动修正边界

可自动修正：tab 转 2 个空格、行尾空白、简单的 `NULL` 到 `nullptr`。`using namespace`、include、命名和类型转换需要语义确认，不由脚本自动删除或重写。

不可自动修正：include 增删或重排、命名、类型转换、所有权、宏逻辑、类接口、const/override、版权文本和任何需要语义判断的变更。
