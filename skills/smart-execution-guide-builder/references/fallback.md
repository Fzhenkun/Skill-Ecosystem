# Fallback

## 输入路径不存在

停止生成，明确列出不存在的原始路径。不要猜测相似目录，也不要创建空指南。若用户同时给出多个路径，只继续处理确认存在且属于请求范围的路径，并说明缺失项。

## 没有找到 Markdown

报告目录中没有找到 `.md` 文件。不要把其他格式静默当成 Markdown；如果需要转换，先等待用户明确要求或说明需要其他工具。

## 文档编码异常

先尝试 UTF-8/UTF-8 BOM。若仍然出现乱码，保留原文件不动，报告具体文件，并说明无法可靠提取的内容。不要用乱码输出覆盖源文件。

## 内容过大

先建立文件和标题索引，再按主题分块读取和归纳。不得因为上下文压力只处理前几份文件；最终要在“原始资料索引”中列出全部输入，并注明无法确认的部分。

## 信息互相冲突

不要擅自选择并隐藏冲突。优先采用用户指定参考文档的表述，或在指南中标记“需按具体约束判断”，同时给出决策条件。

## 输出文件已存在

先检查是否是此前生成的同一指南。默认不覆盖用户已有文件；可以生成带新后缀的文件，或在用户明确允许后覆盖。不要覆盖原始资料。

## 写入或验证失败

停止继续变更，报告失败路径和错误信息。先检查目标目录、编码和权限。不得通过修改工具脚本、删除已有文件或静默跳过验证来强行成功。

## 交付前发现内容缺口

把缺口分为：

- 材料没有覆盖；
- 领域知识需要补充；
- 用户目标尚不明确。

能合理推断的内容可以补充，但必须标记为通用领域补充；不能推断的内容写入“待确认事项”，不要伪造具体结论。
